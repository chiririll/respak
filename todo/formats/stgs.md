# stgs · Settings
**rsx sources:** `game/rtech/assets/settings.h` (`SettingsAssetHeader_v1_t`, `SettingsAssetHeader_v2_t`, `SettingsMod_s`), `game/rtech/assets/settings.cpp` (`LoadSettingsAsset`, `ExportSettingsAsset`) · **Games / versions:** Apex Legends; headers of 72 bytes (v1) and 80 bytes (v2) · **Status:** read + JSON implemented (`respak-respawn/src/stgs.rs`, `stgs_json.rs`), **not yet run against a real pak**. Needs [stlt](stlt.md) to decode values.

## Summary
A settings object: a value buffer whose fields are named and typed by an [stlt](stlt.md) layout, plus "mods" (the item flavor mechanism: a mod overwrites one field of the buffer). Item flavors (`settings/itemflav/...`) are all `stgs`.

## Where it lives
rpak asset, FourCC `stgs` (rsx binds `'sgts'`, `headerAlignment = 8`). The header stores its name (`settings/itemflav/weapon_skin/hemlok/rare_v22_partymusic.rpak`) and **the guid is the hash of that exact string**, `.rpak` included. Checked on `names.txt` / `common.txt`: all 3704 names resolved so far are `stgs`, and every name ends in `.rpak`. rsx adds the stored name to its cache unchanged; respak returns it from `Metadata::name()`.

## Versions and detection
rsx ignores the asset version and picks the header by `headerStructSize`: 72 → v1, 80 → v2, anything else is no asset. respak does the same (`UnsupportedVersion` for other sizes); `Version::new(1|2)` is the header variant, not the pak's asset version.

## Layout
Pointers are page pointers (relocated to `.mem` offsets in the header served by the volume). Offsets: v1 / v2.

| v1 | v2 | Type | Field | Meaning |
|---|---|---|---|---|
| 0x00 | 0x00 | u64 | settingsLayoutGuid | guid of the `stlt` (a guid reference, not a pointer) |
| 0x08 | 0x08 | ptr | valueData | the value buffer |
| 0x10 | 0x10 | ptr→cstr | name | |
| 0x18 | 0x18 | ptr | stringData | string blob; only `string` mods index into it |
| (none) | 0x20 | u8[8] | unk | v2 only, unknown |
| 0x20 | 0x28 | u32 | uniqueID | generated by the bakery, used as the item flavor id |
| 0x24 | 0x2C | u8[4] | | padding? |
| 0x28 | 0x30 | ptr→ptr[] | modNames | `modNameCount` page pointers to strings |
| 0x30 | 0x38 | ptr | modValues | `modValuesCount` × `SettingsMod_s` |
| 0x38 | 0x40 | u32 | valueBufSize | bytes of valueData |
| 0x3C | 0x44 | u32 | singlePlayerModCount | `$modFlags` in rsx |
| 0x40 | 0x48 | u32 | modNameCount | |
| 0x44 | 0x4C | u32 | modValuesCount | |

### `SettingsMod_s` (12 bytes)
| Off | Type | Field | Meaning |
|---|---|---|---|
| 0x00 | u16 | nameIndex | into `modNames` |
| 0x02 | u16 | type | 0 int_add, 1 int_multiply, 2 float_add, 3 float_multiply, 4 bool, 5 number, 6 string |
| 0x04 | u32 | valueOffset | absolute offset of the target field in the value buffer |
| 0x08 | u32 | value | int / float / bool, or a byte offset into `stringData` for `string`; `number` is an int or a float depending on the field |

## Decoding the value buffer
Walk the layout's fields (sorted by offset); the field is at `base + valueOffset`:

| Type | Stored as |
|---|---|
| bool | 1 byte |
| int | i32 |
| float | f32 |
| float2 / float3 | 2 / 3 × f32 |
| string, asset, asset_noprecache | 8-byte page pointer `{page, offset}` **inside `.mem`** (not relocated: resolve with the pak's tables) to a NUL-terminated string |
| static array | inline; elements of the sub layout `subs[valueSubLayoutIdx]`, `arrayValueCount` of them, first at `align(base + valueOffset, sub.alignment)`, spaced by `align(totalBufferSize, alignment)` |
| dynamic array | `{i32 count, i32 offset}`; elements at `offset` from the start of the buffer, same spacing |

## Output
respak: `stgs → stgs.json`: `name`, `guid`, `version`, `layout` (guid), `layoutName`, `uniqueId`, `settings` (field → value; `null` when the layout is not found; float2/float3 as arrays; arrays as arrays of objects), `values` (raw buffer, hex), `modFlags`, `modNames`, `modValues` (`index`, `name`, `type`, `offset`, `raw`, `value`).

rsx differs: it writes `<name's folder>/<stem>.json` with `layoutAsset`, `uniqueId`, `settings`, `$modNames`, `$modValues` (with a `field` access path found by absolute offset), `$modFlags`; float2/float3 as `"<x,y>"` strings, floats with `%f`, and `int_multipy` / `float_multipy` spellings.

## Differences from rsx / quirks
- rsx decodes array elements with `totalLayoutSize` and finds mod targets with the aligned size. respak uses the aligned stride for both (**unverified**; see open question 1).
- respak does not resolve a mod to its field path (`field`) yet, and `number` mods stay `null`.
- Writing is not implemented (it needs pointer-table and guid-reference entries for valueData, name, stringData, modNames, every name and string pointer, and the layout guid).

## Tests
Unit: scalars, vectors, strings, static array with stride padding, dynamic array out of range → `Corrupt` (done). Missing: a synthetic pak with a `stgs` and its `stlt`; the mods; both header sizes. Real (ask first): diff `stgs.json` with the rsx export for a few item flavors and one with arrays.
